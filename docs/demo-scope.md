# Demo 范围与实现状态

## 当前已有

- 浏览器端 Vite + React 应用 Memo Garden；适配窄屏 Android 浏览器。仓库没有 Android 原生工程或 APK 签名配置。
- 泡泡、漫游、共创三页；首页异形泡泡、碰撞和点击反馈仍是浏览器视觉模拟。
- 漫游页提供 8 张独立高反差 SVG 图像识别图，按索引一一对应八段示例声音。点击扫描后使用后置摄像头；MindAR 在浏览器首次扫描时编译 8 张 SVG 并将目标数据缓存到 IndexedDB。每次最多追踪一个图像目标，识别后在目标锚点生成对应 Three.js 泡泡。
- AR 泡泡形态按声音数据呈现圆形、心形、星形、花形或云朵形，有厚度、高光和边缘反射。Android 浏览器支持设备运动事件时，重力/倾斜数据控制泡泡垂直轻浮；传感器不可用时退回低幅环境漂浮。
- 识别目标详情提供示例声音、留言展示和本机演示留言输入。留言提交只更新当前留言抽屉的 React 状态，关闭后会重置；评论后端与跨会话持久化均未实现。泡泡捕捉只由可配置 WebSocket 桥接消息或明确标注的模拟按键触发；播放结束后展示泡泡向右侧屏幕边缘收缩、吸收的状态动画。
- WebSocket 桥接读取 `capture` / `button_pressed` 等消息及 bubbleId / targetIndex，并可显示设备发送的 RSSI。默认没有配置 endpoint，也没有连接真实 ESP32。协议说明见 [ar-image-target-setup.md](./ar-image-target-setup.md)。
- 左下角 Three.js Memo Catcher 模型保留装置 STL 里的吸附手机，不再叠加第二部手机或手模；手机仓、出泡口和弧形握柄可悬停或轻触查看简短说明。产品体验手机仍展示当前 App 原型，手机外壳作为后续替换新版界面与动效的入口。
- Zine 独立预览使用十张风景照片轮播底图，左上角提供选图、前后切换与自动轮播控制。背景泡泡使用 2D 运动、碰撞与屏幕边缘回弹，并以 WebGL2 折射当前照片；这是视觉近似，不等同于真实流体仿真。桌面以十颗大小错落、缓慢起伏的圆形泡泡围绕阅读区，窄屏保留五颗。十页以“一颗泡泡的旅行”串联听见街道、发现地点声音、试听与收集、留下声音和后来者重逢；页面采用现有街景照片的柔焦底图、暖纸色、轻纤维与复印颗粒、手撕照片、错位叠层、剪贴字和手绘线，不使用同一张文案卡片模板。泡泡在 WebGL、减少动态效果和 CSS 降级路径中保留圆、心、花、星、云五种轮廓。字标下的产品介绍是概念文案，不代表当前 Demo 已实现 GPS 声音定位、AI 自动整理或硬件联动；不放入硬件造型插画。翻页采用更慢的速度和更长的拖动距离，并在翻页完成时合成轻微纸页掠过声；移动端前后页按钮固定在安全区内居中显示。
- 首页右上角的物理泡泡入口使用固定步长浏览器物理模拟，包含重力、阻尼、碰撞恢复和弹性形变；合成触地声由实际碰撞速度驱动。泡泡会淡入现有制作过程球形画廊并支持返回。该转场与声音都是网页视觉/音频模拟，不代表真实液体、实体泡泡装置或硬件控制。
- 制作过程页以五个阶段承载照片与短视频。球体持续缓慢自转；球内滚轮和方向键切换阶段，当前层清晰、其他层降低饱和度；素材按进入顺序随机排列，分页不重复。视频使用浏览器通用的 H.264 MP4 编码，并保留播放失败提示。
- SwiftUI Liquid Glass 视觉原型 `native/SoundscapeDemoView.swift`；未在 Xcode 工程中编译验证。

## 当前真实能力与模拟边界

- 摄像头画面来自浏览器真实相机，需 HTTPS/localhost 和用户授权。MindAR 对提供的印刷图像运行特征检测；目标需在画面内才能维持追踪，目标丢失后 AR 锚点也会丢失。它不是 GPS 地理锚点或持久空间锚点。
- 首次扫描会从 CDN 加载 MindAR/Three.js 并在浏览器编译目标库；需要网络。编译结果只缓存到当前浏览器的 IndexedDB。
- 运动传感器是否可读取决于浏览器、权限和设备；传感器未授权时仍显示环境漂浮。该效果不等同于 ARCore/ARKit 世界追踪。
- 网页不能扫描附近 Wi-Fi 信号，也不能读取任意模块 RSSI。真实设备需加入同网络 WebSocket 桥接服务并按协议主动发送按键/状态消息；默认 endpoint 为空，界面提供显式演示按钮。ESP32 固件、配网、认证、重连和实体按键尚未集成或验证。
- 共创页会在获得麦克风权限后录制最多 30 秒音频，支持本机试听，并可将录音加入当前会话的 Gallery；对象 URL 在离开应用时释放，不上传、不跨设备同步，也没有自动转写或声音分离。
- 预置声音仍使用文本语音合成；AR 评论与回声榜留言是演示数据，新增 AR 留言只存于当前页面组件状态，关闭抽屉或刷新页面后不会保留。没有评论 API、数据库或跨设备同步。
- 捕捉水流、浮动、播放后吸收及加载完成时的飞泡动效是 CSS/SVG/Canvas 和 Three.js 编排的视觉反馈，不是流体仿真；网页不控制机械吹泡泡。
- 当前仓库没有账号、服务端、数据库、真实 GPS 数据、Android 原生 APK 工程或签名配置。

## 后续集成方向

1. 与装置团队确定 ESP32 Wi-Fi 连接方式、WebSocket bridge 地址、认证与消息字段，并在 Android 实机验证实体按键到 UI 的时延与断线恢复。
2. 在 Demo Day 打印并现场测试 8 张识别图的尺寸、照明、反光、识别距离与丢失恢复；必要时为固定展台预渲染 MindAR `.mind` 数据，避免首次编译等待。
3. 如需声音泡泡在摄像头离开识别图后仍停留空间中，评估 Android ARCore 持久锚点；如需按真实地点长期复现，再单独接 GPS/Geospatial 能力。
4. 接入录音持久化、评论同步与真实机械泡泡装置。
5. 建立 Android 原生工程和 APK 签名/发布流程。

上述条目是集成方向，不代表已经完成。
