# 产品上下文

## 产品是什么

声景漫游是一个智能声景捕捉器：人们在城市中漫游，发现其他人留在真实地点的声音泡泡，再用手机和实体装置共同完成捕捉与播放。每个泡泡是一段与 GPS 坐标绑定的 UGC 声音；街道和旅程是探索空间，不依赖预先定义的景点列表。

## 用户体验闭环

1. 用户打开 App，看到附近漂浮的声音泡泡或自己的泡泡收藏。
2. 用户开始漫游，手机摄像头画面叠加 AR 声音泡泡；通过取景和缩放选择目标，包括视觉上位于高处的泡泡。
3. 体验者或观众参与共选。用户对准后按下实体装置上的物理按键，触发捕捉。
4. 手机 UI 表现泡泡被吸入装置；装置播放对应声音，并在播放时吹出真实泡泡。大屏同步显示目标、捕捉和播放状态。
5. 用户也可以在 App 中录下一句话，选择“给下一位”或“留在此刻”。录音会绑定当前位置，经过处理和试听后发布为新的公共泡泡。
6. 新泡泡留在录制时的 GPS 点位，之后路过的人可以再次发现。

## 公共泡泡与个人收藏

- **公共原泡泡**：发布后固定在录制位置，可被后来路过的人发现。
- **捕捉记录**：捕捉者获得个人收藏/回听记录。捕捉不会删除公共原泡泡。
- **个人创作**：创作者录制的音频发布后也成为公共原泡泡，同时保留在创作者的“我留下的”列表中。
- **发现方式**：地图位置来自用户旅程中的连续 GPS 点位，不是只在景点或打卡点生成。

## 信息架构

### 泡泡

首页和回听入口。用户浏览不同大小的透明声音泡泡，点击可触发挤压、回弹、破裂动画并听见声音；个人收藏从泡泡页进入，不额外增加主导航项。设备连接状态轻量显示在顶部。

首页可按“共鸣最多 / 离我最近 / 刚刚留下”排序。收藏较多的声音通过柔和虹彩光晕突出；“回声榜”聚合附近的高共鸣声音，让现场体验者与观众一起选下一颗要找的泡泡。榜单不发积分、不消耗声音。

### 漫游

沉浸式 AR 取景。真实街道画面作为空间背景，泡泡按距离和视觉高度浮在街景中；用户缩放和瞄准，现场共同选出目标，再按实体按键捕捉。捕捉后展示手机、实体设备和大屏的同步播放反馈。

### 共创

App 内录音。用户选择“给下一位”或“留在此刻”，录音后试听处理结果，确认 GPS 位置和公开范围，再发布。

### 现场镜像

Demo Day 的大屏跟随手机当前状态显示。让旁观者看清目标泡泡、共选状态、捕捉结果及装置播放过程；大屏也应支持观众参与选泡泡或成为声音创作者。

## 游戏化方向

- 以“走出去发现声音”为主，不靠连续签到或积分榜驱动。
- 用泡泡收藏、街区声音集、漫游路径和轻量探索目标反馈进度。
- 多人共选让现场观众参与目标选择；“给下一位”让 UGC 形成可接续的声音关系。
- 用收藏热度、附近排序和短榜单制造轻量发现目标。被捕捉后公共泡泡仍留在原坐标，不把街道声音变成被抢完的掉落物。
- 具体任务和奖励不应破坏“泡泡来自真实录制位置”这一规则。

## 软硬件分工

| 手机 App | 实体声景装置 |
| --- | --- |
| 摄像头 AR 取景、定位和目标选择 | 物理按键触发捕捉 |
| 录制、声纹处理流程、位置绑定和发布 | 播放捕捉到的声音 |
| 泡泡详情、收藏、社交共选 | 播放时吹出真实泡泡 |
| 手机 UI 状态与大屏同步 | ESP32 Wi-Fi 与手机通信（目标方案） |

## 关键交互状态

- 泡泡：附近可发现 → 被选中 → 已捕捉到个人收藏 → 可回听；公共原泡泡仍留在原坐标。
- 设备：未连接 → 已连接 → 等待实体键 → 正在播放/吹泡泡 → 播放完成。
- 共创：选提示 → 录音 → 处理其他人声 → 试听 → 确认位置/可见范围 → 发布成功。
- 弹窗：优先用轻量底部抽屉或小型状态卡，只说明当前状态和下一步操作。

## 当前设计假设

- 主导航为“泡泡 / 漫游 / 共创”三项；个人收藏位于泡泡页，不额外增加主导航项。
- 公共声音在 GPS 点位长期存在；捕捉不会让后来者失去这个声音。
- 对楼层或室内高度的视觉演示，可以用预设场景坐标表现；普通 GPS 本身不应被描述为可稳定区分楼层。
