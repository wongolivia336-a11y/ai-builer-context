# Memo Garden 视觉与交互修复设计

日期：2026-11-20
目标仓库：wongolivia336-a11y/ai-builer-context
实施基线：用户指定的本地副本 memo-garden-fix，当前分支 codex/memo-garden-visual-fixes-20261120。先前比对确认该副本跟踪文件与 GitHub 当前 main 文件树一致；不以外层 Knock Knock 工作区或旧版 soundscape-glass-demo 作为实施基线。

## 目标与范围

本轮覆盖用户给出的完整待办清单。优先修复已明确报告的问题：装置手机方向、单手握持、轨道文字挤压邻泡、一次点击破裂、漫游说明文字过多、摄像头权限/错误反馈、共创拉杆过小。对其余清单逐项检查当前实现；已满足的保留并验证，缺失或有明显体验问题的按下列验收补齐，不重做已正常的功能。

## 设计与实现范围

### 1. 首页泡泡层次、文字轨道与交互

- 泡泡尺寸和轮廓有清楚变化，减少大块留白；优先使用现有资源与轻量 CSS/SVG 形状，让圆形、心形、星形、花形等轮廓仍保持统一的细腻材质。
- 轨道文字沿泡泡轮廓排布，控制字数和对比度；面向用户的一侧清晰，转到背面的字弱化或隐藏。形状不规则时仍贴合外轮廓，并保留独立无障碍名称。
- 轨道文字为装饰层，不进入泡泡碰撞半径、边界约束、位置或挤压计算；聚焦时文字显隐不得带动邻泡改变轨迹或形状。
- 泡泡可直接拖动；真实重叠时做柔和挤压与回弹，避免轨道文字或装饰层参与挤压；控制同时运行的动画数量和帧率，兼顾手机负载。
- 修复拖拽后点击被抑制的状态生命周期。普通点击、触屏轻触及键盘激活都应一次触发破裂；真实拖拽不触发破裂。
- 保留项目现有 Canvas 破裂层，改进单击命中与粒子生成、衰减和回收。视觉目标是一次触发、快速液态收缩/撕裂、少量短寿命碎滴后消散；移动端限制粒子数量，避免常驻重动画。
- 参考 Sparkle 开源项目的单次 hit-test 和短生命周期 Canvas 粒子组织方式，按本项目架构重写交互，不新增运行时依赖、不复制其实现代码。参考：[Sparkle Bubbles API](https://sparkle.graphics/api/bubbles)、[Sparkle layer.ts](https://github.com/basmilius/sparkle/blob/main/src/bubbles/layer.ts)。

### 2. Tab 导航与移动端布局

- 检查各级 tab 的实际切换和底部锚点；切换有轻量弹性和连带形变，保留荧光草绿色呼应。
- 修复底部 tab 点击导致页面跳顶、错位、遮挡或触摸区域过小的问题。
- 动效优先使用短时、事件驱动的 transform/opacity；不引入重型常驻动画。检查 390×844 手机尺寸和桌面宽屏。

### 3. 漫游与 AR 摄像头体验

- 移除漫游画面中的说明性/注释性段落；保留必要的扫描状态、泡泡名称、主要操作、无障碍标签、错误恢复指引，以及无设备端点时明确的 Demo 标记。
- 在用户主动点击扫描时，尽早启动浏览器相机权限流程；区分不安全上下文、权限拒绝、无摄像头、摄像头占用/不可读、MindAR 或 CDN 初始化失败，并给出对应的短提示和重试入口。
- 如 MindAR 接口支持，明确选择后置摄像头；保留既定的 8 张单独 SVG 图片目标、识别位置、泡泡呈现/缩放/设备重力漂浮/捕捉动画和播放后的屏幕右侧吸收流程。
- 真实 Android HTTPS、相机识别位置、重力方向及 Android WebView import map/权限/motion 兼容需尽可能验证；若当前没有可用设备，则明确列为未验证，不声称完成。

### 4. 共创与声音泡泡

- 将拉杆及可点击区域放大，呈现明确的“按下开始 / 再按停止”状态和触觉式把手层级。
- 将录音控制卡紧邻并视觉连接到主泡泡，让拉杆成为卡片的核心操作；录音中主泡泡随输入声音和时长呼吸、抖动、膨胀并有克制的波浪形变，不引入重型常驻动画。
- 停止后形成可保存/发布的声音泡泡，并核对演示数据/浏览器内存状态；如果当前没有服务端持久化，则在界面或产品说明中明示原型保存范围，不暗示云端保存。
- 390×844 下检查卡片留白、主泡泡与拉杆占位、点击区域和底部 tab；同时检查桌面宽屏。

### 5. EchoCaster / Memo Catcher 模型

- 统一装置主体、手机槽位和手部模型的朝向变换，避免手机模型脱离装置或屏幕朝向观众相反。
- 只保留一个清楚的单手握持姿势；手掌、拇指、四指和握柄关系一眼可读，不做双手交叉效果。
- 以桌面模型视角和手机宽屏截图检查组合关系；只在不改变装置核心结构的前提下微调握持比例、倾角和握柄可见度。若热点交互已有实现，检查 hover 形变和设计说明可读性，不为此引入重型动效。

### 6. 数据、设备边界与说明

- 检查评论是否仅存在内存/演示数据中，并在产品说明中明确后端持久化尚未实现。
- 设备 WebSocket 继续由 ?deviceWs= 或 VITE_ECHOCASTER_WS 配置；无端点时明确显示 Demo 模式。不会描述网页能任意扫描 Wi-Fi/RSSI，也不会声称已验证 ESP32 固件、真实 Wi-Fi 模块或硬件桥接。

### 7. 资产交接包与 README

交付两个内容相同、便于复制的独立资产包副本：项目中的资产包目录和单独的 ZIP 备份。包括：

- 现有插画/UI/WebP 视觉资产；
- 8 张单独可下载的高对比黑白 SVG 识别图及对应泡泡名称映射；
- EchoCaster 预览图和可合法分发的模型源资产；
- 产品命名、UI 色板、字体/材质线索、资产用途和文件清单；
- 每个文件的 SHA-256 清单，方便同学检查拷贝完整性。

README 面向人和 coding agent，写明项目与产品命名、目录索引、启动/构建方式、视觉 token、8 个目标图的映射、资产包位置、已确认部署地址。仅记录可从 PR/Vercel 明确验证的预览 URL；若生产域名不能验证，标注“未确认”，不猜测。

## 技术边界

- Web 原型仍使用 React、Vite、Three.js 和 MindAR；MindAR/Three.js 依赖仍由 index.html import map 从 CDN 提供。
- ImageTargetARStage.jsx 继续使用运行时 import helper；不改回会被 Vite 静态解析的字面量导入。
- 不修改 SwiftUI 原型。
- 无设备端点时保持明确 Demo 模式；不声称已实现真实 RSSI、Wi-Fi 扫描、ESP32 联动或硬件验证。

## 验收方式

1. 在用户指定副本的新独立修复分支上实施；PR 以最新 GitHub main 为基线，避免重复展示已合并的旧提交；不合并 PR。
2. 逐项对照本设计中的首页、tab、漫游/AR、共创、模型和数据边界要求；现有功能已满足的记录验证结果，缺失或有问题的修复。
3. 泡泡轨道显隐不改变邻泡物理；拖动和重叠反馈顺滑；拖动后下次单击不被吞；一次轻触即可看到完整破裂反馈。
4. 漫游页说明性文字移除；摄像头常见失败情形有可操作的解释和重试。
5. 共创拉杆在手机上易见、易点且与主泡泡有清楚联系；评论/录音的持久化边界表述准确。
6. 运行用户明确要求的 npm run build；做 390×844 和桌面宽屏走查。真实 Android 验证情况单独注明。
7. README、资产包目录、ZIP 备份与校验清单互相一致；预览地址有来源可核验。
