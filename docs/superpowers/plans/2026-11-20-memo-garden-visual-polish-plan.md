# Memo Garden 视觉与交互修复实施计划

1. 版本与现状
   - 以用户指定的 memo-garden-fix 文件夹为唯一工作副本。
   - 保留原有 codex/memo-catcher-ui-cleanup-20261120 分支。
   - 从已核对为相同文件树的最新 GitHub main 建立全新修复分支，避免旧 PR 提交进入差异。
   - 对首页泡泡、tab、漫游/AR、共创、模型、数据说明和当前断点逐项盘点；已满足的只记录验证，不重写。

2. 首页泡泡与轨道
   - 从 Home 物理边界和碰撞计算中移除 orbit 文本的 padding；保证文字显隐不改变泡泡尺寸、运动或邻泡形变。
   - 修复 pointer/touch 拖动阈值及 suppress-click 清理；单击和键盘激活一次破裂，拖动不破裂。
   - 保留现有 Canvas 破裂实现，移植适配单击 hit-test、短生命周期粒子衰减与移动端数量限制。
   - 审视形状、大小、外轨道前后遮挡和挤压回弹；只补缺少的轻量实现，保持 8 个泡泡的语义与可读性。

3. 页面导航与共创
   - 检查底部 tab 锚点和移动端 390×844 的切换；修正跳顶、遮挡、点击区和位置。
   - 将拉杆与其 hit target 放大，重新组织中心录音卡和主泡泡关系；检查录音呼吸反馈、停止后的保存/发布状态及其真实持久化范围。
   - 仅用短时、事件驱动动效。

4. 漫游与 AR
   - 删除漫游说明性文字，保留状态、控制、必要错误恢复、无障碍标签和 Demo 标记。
   - 区分安全上下文、权限、无相机、相机繁忙/不可读、引擎/CDN 初始化错误；在明确用户操作后尽早触发相机请求，并提供可重试入口。
   - 保持 8 张单独目标图、runtime import helper 与既有泡泡跟踪交互；检查后置相机设置是否可用。
   - 检查 WebSocket 演示模式和评论内存态说明，不扩大硬件或服务端实现承诺。

5. Memo Catcher 模型
   - 统一主体、手机托架及握手模型的父级朝向和坐标变换。
   - 删除可读成第二只手/交叉双手的几何，只保留一个握持关系清楚的手。
   - 在模型预览中校准屏幕朝向、手柄和整体装配关系。

6. 资产交接与 README
   - 准备独立资产目录和一份内容一致的 ZIP 备份。
   - 收集现有插画/UI 资产、8 张 SVG target、预览图和允许分发的模型源资产；生成带 SHA-256 的清单。
   - 写入产品名称、色板、资产索引、8 张 target 映射、启动/构建方式、Agent 阅读顺序和已确认的部署预览地址。无法确认的生产域名写明未确认。

7. 走查与交付
   - 执行用户要求的 npm run build。
   - 用 390×844 和桌面宽屏检查关键 UI，修复实际出现的错位/遮挡/操作问题。
   - 记录 Android HTTPS、WebView、设备桥接未能在真实设备验证的边界。
   - 汇总根因、修改、构建结果、PR 和资产包位置；不合并 PR。
